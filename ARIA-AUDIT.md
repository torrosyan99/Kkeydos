# Аудит ARIA

Проверены 83 HTML-страницы в `app`, включая новую `services/ai-development.html`, шаблоны HTML в `tools/build_blog_articles.py`, SVG с ARIA, общие и страничные скрипты, CSS-селекторы ARIA в `src` и собранных стилях. Исходной точкой была рабочая копия с уже существовавшими изменениями, а не HEAD Git.

## Изменения

- Имена элементов берутся из видимого текста или `alt`; `aria-label` применяется к иконочным элементам, различимым областям навигации и полям без видимого `<label>`.
- Удалены 23 подписи ссылок, дублировавшие видимый текст `Our clients`.
- 164 ссылки с логотипами получают имя из `alt` изображения. Для ссылки `/` указано назначение домашней страницы; для существующей ссылки `#` — переход к началу текущей страницы. Адреса ссылок сохранены.
- Удалены 43 необязательных названия областей: повторяющиеся CTA-секции и единственная боковая область статей. Шаблон генератора статей исправлен аналогично.
- По уточнённому требованию пользователя удалены 305 скрытых `<label class="sr-only">` на 67 страницах. Для 261 поля без видимой подписи используется `aria-label`; существующие видимые `<label>` сохранены. В формах нет скрытых элементов, добавленных только ради подписи.
- Все 44 селектора телефонного кода используют одну схему: кнопка имеет `aria-label="Country calling code"`, а `aria-labelledby` ссылается на саму кнопку и элемент текущего значения. Это даёт имя вида `Country calling code IN +91`, которое обновляется при выборе страны без изменения JavaScript. Listbox имеет `aria-label="Country calling code"`. Скрытый `input` с выбранным кодом, состояния и атрибуты отправки формы сохранены.
- 82 кнопки мобильного меню имеют постоянное имя `Menu`, исходное состояние `aria-expanded="false"` и ссылку `aria-controls` на панель. Существующий JavaScript продолжает обновлять состояние.
- 144 мобильные панели технологий получили отсутствовавшие ID. Существующий JavaScript теперь записывает действительные цели `aria-controls` при переключении между мобильным и десктопным представлением.
- На трёх страницах категорий блога `aria-current="page"` перенесён с `All` на соответствующую категорию.
- `<head>` новой страницы оформлен по шаблону страниц отраслей. Сохранены общие метаданные, относительные пути ресурсов и модульный `main.js`. Удалено подключение `industry.js`: на новой странице нет необходимого ему `[data-fixed-content]`, и до исправления он вызывал `Cannot read properties of null (reading 'querySelector')`.

Сохранены подписи иконочных ссылок, социальных кнопок, каруселей, различимых областей навигации и прокручиваемых областей. У кнопок Previous/Next текст скрывается на узких экранах, поэтому доступное имя требуется и после адаптивного переключения. Сохранены `aria-hidden` декоративных элементов, `role="status"`, состояния аккордеонов, `aria-selected` вариантов, `aria-current="location"` оглавления и ARIA, создаваемая Swiper.

В рамках этих исправлений файлы JavaScript и CSS не изменены. Существующие классы, ID элементов управления, `data-*`, адреса ссылок и обработчики сохранены. Удалены только скрытые подписи и их больше не используемые связи; зависимости от скриптов и стилей предварительно проверены. Существующие скрытые радиокнопки и сообщения `role="status"` сохранены: это функциональные элементы, а не подписи полей.

## Проверки

Использованы локальный HTTP-сервер, Playwright, headless Chrome и axe-core 4.10.3. Проверки не отправляют формы и не переходят по внешним ссылкам.

Первоначальный браузерный обход: 82 из 82 страниц прошли проверки, нарушений выбранных правил axe — 0, ошибок выполнения JavaScript — 0. После уточнения требований все 67 страниц с изменёнными формами повторно прошли проверки: нарушений выбранных правил axe и ошибок JavaScript — 0. Новая страница также проверена отдельным сценарием. Эти результаты относятся к перечисленным сценариям и правилам; ограничения поведения указаны ниже.

- Проверка исходников всех 83 страниц после уточнения: отсутствие скрытых `<label>`, доступные имена полей, единая схема 44 селекторов, отсутствие дублирующихся ID, сохранность видимого текста, элементов управления и атрибутов, не относящихся к ARIA.
- Браузерный обход всех страниц на десктопе и мобильном: выбранные правила axe для допустимых ARIA, доступных имён кнопок, ссылок и полей; проверка целей `aria-controls`, `aria-labelledby`, `aria-describedby`.
- Открытие и закрытие мобильного меню, раскрытие его четырёх разделов; активация FAQ с клавиатуры; выбор значений форм и проверка `aria-selected`, текста кнопки и скрытого поля; раскрытие панелей технологий.
- Отдельные сценарии трёх каруселей, оглавлений, бизнес-блоков и категорий блога.
- Сравнение геометрии и вычисленных стилей 12 типов страниц при ширине 1440 и 390 px: все 24 сравнения совпали. Скрипты и анимации отключались только в тестовом браузере для стабильного сравнения. Это проверка исходной вёрстки; интерактивность проверялась отдельно с включённым JavaScript.
- После удаления скрытых подписей повторены 12 сравнений шести типов страниц при ширине 1440 и 390 px: вёрстка и стили совпали. На новой странице отдельно проверены меню, все девять FAQ, выбор страны, доступное имя выбранного кода и ARIA открытого списка. Ошибок выбранных правил axe и JavaScript на новой странице нет.
- `git diff --check`: без ошибок пробелов.

Локальные сценарии и JSON-результаты находятся в `tmp/verify-aria.mjs`, `tmp/verify-aria-source.mjs`, `tmp/aria-scan-results.json`, `tmp/aria-layout-results.json`, `tmp/aria-components-results.json`. Папка `tmp` исключена из Git. Сценарии используют уже установленный Playwright в `tmp/blog-nav/tools/node_modules` и временно загруженный `tmp/axe.min.js`; зависимости приложения не менялись.

Актуальные результаты повторной проверки форм: `tmp/verify-form-source.mjs`, `tmp/aria-forms-results.json`, `tmp/aria-forms-layout-results.json`, `tmp/aria-service-results.json`.

## Прежние ограничения, требующие изменений поведения

Это исправление разметки не является подтверждением полного соответствия WCAG. Ограничения ниже воспроизведены на исходной и изменённой версиях:

1. Пользовательские списки `.select` в `app/assets/scripts/main.js` не переводят фокус по ArrowDown и не закрываются по Escape. Активация кнопок и выбор варианта через Enter работают, но для полноценного поведения listbox нужны управление фокусом и клавиатурные обработчики. Существующие `role="listbox"`, `role="option"` и `aria-selected` сохранены: состояние выбора используется JavaScript и CSS.
2. Карточки `[data-technology-card]` в `app/assets/scripts/pages/technology.js` раскрываются обработчиком `click` на `<li>`. Скрипт добавляет `aria-expanded` после клика, но карточка не получает клавиатурный фокус и не имеет клавиатурного обработчика. Для исправления необходим пересмотр управляющего элемента и его событий.

Эти изменения не внесены в соответствии с запретом менять JavaScript-логику и существующий функционал. Сравнение поведения сохранено в `tmp/aria-limitations-results.json`. Проверка настоящими скринридерами не проводилась.

## Основания

- [WAI: доступные имена и описания](https://www.w3.org/WAI/ARIA/apg/practices/names-and-descriptions/) — предпочтение видимого текста и нативных механизмов имени.
- [WAI: подписи полей](https://www.w3.org/WAI/tutorials/forms/labels/) — связь `<label>` с элементом формы.
- [WAI: раскрывающиеся компоненты](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) — состояние `aria-expanded` и связь с содержимым.
- [WAI: listbox](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) — клавиатурное взаимодействие и состояния выбора.
